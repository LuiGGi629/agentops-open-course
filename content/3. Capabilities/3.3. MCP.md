- **You will:** Inspect MCP roles, transports, protocol negotiation, readiness, and the client allowlist without calling a model.
- **You need:** The tool tests passing; a second terminal for the HTTP probe.
- **Time:** about 35 minutes, hands-on. {{% /admonition %}}

## What problem does MCP solve?

MCP separates a tool consumer from the process that owns the capability.

```bash
cd agents/go
go test ./mcpserver ./compose
```

The agent no longer needs to link every read implementation into its conversational entrypoint. A local child process, host service, gateway route, or Kubernetes service can expose the same typed tool declarations and calls over a standard protocol.

## What are the parts of MCP?

The course uses four roles.

- The Go MCP **server** registers six read tools.
- ADK's Go MCP **toolset** is the client adapter inside the agent.
- A **transport** carries JSON-RPC over stdio, legacy SSE, or streamable HTTP.
- agentgateway is an optional **policy point** between client and server.

MCP governs tool discovery and invocation. A2A governs agent discovery and task exchange; neither replaces the other.

## How do you inspect the MCP server without a model?

Start streamable HTTP in one terminal:

```bash
cd agents/go
mise run mcp:http
```

Probe it from another terminal:

```bash
xh GET http://127.0.0.1:8000/livez
xh GET http://127.0.0.1:8000/healthz
```

The protocol handshake and exact six-tool listing are covered offline:

```bash
cd agents/go
go test ./mcpserver ./compose
```

## Why does MCP matter beyond this repository?

The wire boundary lets independently deployed clients and servers evolve behind a negotiated protocol instead of sharing an implementation language or package tree.

That portability also creates risk: tool names, descriptions, and schemas are instruction-like model input. The client must authenticate the route when required, apply timeouts, and filter the accepted tool names.

## Which tools does the course server expose?

Exactly the six read tools from [3.1. Tools]({{< relref "/3. Capabilities/3.1. Tools.md#which-read-tools-does-the-agent-expose" >}}).

The server does not register `restart_service`, `resolve_incident`, long-term memory writes, arbitrary SQL, files, prompts, or resources. Server and client tests compare the registered surface with `compose.MCPReadToolNames()`.

## Which revision of MCP are you speaking?

The pinned `github.com/modelcontextprotocol/go-sdk` negotiates the protocol revision with the peer.

Do not copy a revision number into configuration. `agents/go/go.mod`, `go.sum`, the installed SDK source, and the handshake tests are the authority. An SDK upgrade must re-run both stdio and HTTP protocol tests plus the gateway smoke.

## Which transports are supported?

The Go server supports stdio, streamable HTTP, and legacy SSE compatibility.

{{< include path="agents/go/mcpserver/transport.go" region="mcp-server-transport" lang="go" >}}

- **stdio** is the default local child-process path and publishes no port.
- **streamable HTTP** serves `/mcp` and is the host gateway and Kubernetes path.
- **SSE** keeps compatibility with older clients; new deployments use streamable HTTP.

HTTP defaults to loopback and applies Host and Origin allowlists, header timeouts, and bounded drain.

## How does the MCP server report readiness?

`/livez` reports the process loop. `/healthz` additionally proves the configured seed and runtime stores are readable and correctly shaped.

Readiness is strictly read-only. The MCP process does not prepare, migrate, or publish writable state; those operations belong to A2A startup and direct write boundaries.

## How does the MCP helper choose a transport?

`compose.NewMCPToolset` accepts either an HTTP endpoint or an explicit child command.

{{< include path="agents/go/compose/mcp.go" region="ops-mcp-toolset" lang="go" >}}

An HTTP endpoint receives a bounded `http.Client` and optional bearer credential. A child command uses the SDK command transport and no network credential. Supplying neither is a configuration error.

## What does the stdio transport actually launch?

The caller names the same Go agent binary with the `mcp` subcommand.

The child inherits only the environment deliberately provided by its parent, communicates over standard input/output, and exits with the parent. It does not require a shell or a second runtime.

## When does the root agent use MCP?

Only the conversational entrypoint switches its six reads when `AGENT_MCP_URL` is present.

The workflow and coordinator retain local, restricted tools. Writes remain in-process. This prevents a remote server from acquiring action authority merely because the read path moved behind a protocol.

## What changes when you flip `AGENT_MCP_URL`?

The tool implementation location changes; the model-facing names and schemas do not.

The client connects at runtime, discovers declarations, keeps only `MCPReadToolNames()`, and applies the tool timeout. A compromised server cannot add an extra tool or inject its description into the request through an unapproved name.

## Why put agentgateway between the client and server?

The gateway centralizes authentication, authorization, allowlists, rate limits, telemetry, and failure policy for networked tool traffic.

It does not replace server-side validation or the client allowlist. Chapter 5 proves the direct and governed surfaces separately.

## How would you add a third-party MCP server safely?

Treat it as untrusted code and untrusted instruction data.

1. Review provenance, license, transport, authentication, and tool schemas.
1. Create a closed client-side name allowlist.
1. Give the server only the data and network access its tools need.
1. Apply deadlines, size bounds, redaction, and audit evidence.
1. Test an extra advertised tool and confirm it never reaches the model.
