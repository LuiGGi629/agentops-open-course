## What builds this site?

Hugo Extended renders Markdown through the Hextra theme. Both Hugo and the theme are pinned: the executable in root `mise.toml`, and the theme as a Hugo Module in root `go.mod` and `go.sum`.

```bash
mise run build:docs
```

The build writes `site/`. It makes no network deployment and proves only that the current checkout renders locally.

## Where does each documentation concern live?

| Concern                              | Authority                                          |
| ------------------------------------ | -------------------------------------------------- |
| Site configuration and source mounts | `hugo.toml`                                        |
| Theme version                        | root `go.mod` and `go.sum`                         |
| Hand-ordered learning path           | `data/nav.yaml`                                    |
| Page content                         | `content/`                                         |
| Source include shortcode             | `layouts/_shortcodes/include.html`                 |
| Include extraction                   | `layouts/_partials/include/`                       |
| Admonitions and collapsibles         | `layouts/_shortcodes/` and `assets/css/custom.css` |

| Search route index                   | `assets/json/search-data.json`                     |
| Vendor asset pins                    | `assets/js/vendor/versions.json`                   |

The navigation file is deliberate. Filesystem order alone cannot express the learner path reliably.

## What does the FAQ frame enforce?

Every page declares `title` and a one-sentence `description`. Every non-home page also declares one lowercase kebab-case `slug`; home alone omits it. The body starts with “In one glance,” every H2 is a question, and the page ends with a proof checkpoint.

Chapter indexes use `What proves this chapter worked?`. Pure lookup pages use `How should you use this page later?`. Technical pages use `What proves this page worked?`.

The convention checker parses the structure rather than pattern-matching a few lines, so malformed front matter, missing pages, and misplaced includes fail with source context.

## How do reviewed slugs become public permalinks?

The source tree keeps readable numbered directories and filenames, while front matter owns reviewed route segments.

Each chapter section has a slug such as `2-agents`; each regular page has a slug such as `2-1-first-agent`. The permalink rules in `hugo.toml` combine `:sectionslugs` with `:slug`, producing `/2-agents/2-1-first-agent/` without copying the chapter path into every page.

Do not add a complete front-matter `url`: Hugo gives it precedence, so it would silently shadow the reviewed slug. Home stays at `/` without a manufactured slug. When a slug changes, update navigation and incoming links in the same change.

The conventions gate derives routes from source slugs and the Hugo configuration. After rendering, it checks uniqueness, hierarchy, trailing slashes, canonical and Open Graph URLs, sitemap, search index, navigation links, and edit links rather than consulting a second route manifest.

## How do source includes stay exact?

An include names a repository path, region, and language:

```text
{{</* include path="agents/go/model/model.go" region="build-model" lang="go" */>}}
```

The source carries exactly one `--8<-- [start:build-model]` and one matching end marker. Hugo reads mounted assets, extracts and dedents the region, then highlights it.

A missing file, missing region, duplicate marker, empty region, absolute path, or parent traversal fails the build. The shortcode must stand alone outside a fenced code block because it renders its own block.

`hugo.toml` mounts `agents/`, `evals/`, `tools/`, `infra/`, `scripts/`, and workflow sources under `assets/source/`. Hugo server therefore rebuilds when quoted code changes.

## What makes the build strict?

Three controls combine into strict mode:

1. `build:docs` passes `--panicOnWarning`.
1. `hugo.toml` sets reference-link errors to `ERROR`.
1. The navigation checker rejects any course page absent from the hand-ordered navigation.

There is no single switch that replaces all three. Removing one weakens a distinct failure boundary.

## How do diagrams remain accessible?

Every new or changed Mermaid diagram has adjacent `**Diagram in words:**` prose that describes actors, relationships, and sequence without relying on color.

Link dense unfamiliar terms to the glossary, use descriptive link labels, keep headings hierarchical, and verify keyboard and screen-reader behavior through the browser accessibility gate.

Previously reviewed diagrams are tracked by an exact-hash ratchet. That list is not permission to exempt new diagrams.

## How do you preview and validate a page?

Use one terminal for the preview:

```bash
mise run serve
```

Use another for the gates:

```bash
mise run check:docs
mise run check:links
mise run check:accessibility
mise run build:docs
```

Inspect each changed page at desktop and narrow widths. Check headings, tables, code overflow, focus order, link names, admonitions, and diagram descriptions.

## How are time-sensitive claims kept honest?

Version authority lives in locks and manifests, not prose. Refresh costs, model compatibility, image sizes, test counts, and timings against the current candidate before repeating them.

The freshness gate reports surfaces that need review. It does not make an unverified external claim true and does not authorize a cloud change.

Measured coverage belongs in local evidence, not policy. No Go coverage threshold is enforced because the owner has not selected one.

## Does this repository publish the site?

No. This checkout is the Hugo evaluation build. Its `baseURL` preserves canonical and social metadata for comparison, but no Pages workflow, CNAME, DNS record, or deployment contract ships here.

Publication, repository identity, version lineage, URL redirects, DNS, TLS, and anonymous-clone proof remain owner-gated. A successful local build is not public-site proof.

## What should a documentation contribution include?

Keep one coherent change:

1. Update the source contract first when behavior changes.
1. Update every affected course page and public contract document.
1. Add or adjust named include regions only around stable source excerpts.
1. Run formatting, structure, links, accessibility, and Hugo build gates.
1. Inspect the rendered pages and final diff.

Do not duplicate an implementation into prose. Quote the smallest exact excerpt and explain the decision around it.
