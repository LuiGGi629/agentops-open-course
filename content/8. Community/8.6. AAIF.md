{{% admonition abstract "In one glance" %}}

- **You will:** Map each open contract in this stack to its steward and its exact pin, then route a sanitized failure to the narrowest owner.
- **You need:** Nothing running; check the current project pages before filing anything.
- **Time:** about 12 minutes, reference. {{% /admonition %}}

## Four projects, one broken turn, and nobody's name on it

An A2A task comes back with a protocol error at 17:40. The agent is fine, the gateway is up, the model answered. Somewhere between an SDK, a specification, a proxy, and a collector, something disagreed about a field — and you are about to file an issue. File it in the wrong tracker and it sits for three weeks; file it with your whole checkout attached and it sits forever.

The reason this is hard is also the reason the stack is any good: an agent crosses contracts maintained by different communities, so no single vendor silently owns every seam. Four protocol families keep the implementation replaceable. **MCP** connects agents to read-only tools and data. **A2A** exposes agent discovery, messages, tasks, streaming, and cancellation. The **OpenAI-compatible Responses** API connects the local Go model adapter to Ollama or to the gateway. **OTLP** carries traces, metrics, and logs to the collector. OCI and Kubernetes contracts then package and deploy the same application. Every one of those is open; every use of it here is pinned and tested.

## Stewardship names a project; a lock names the bytes

Open governance gives a project public contribution rules, security routes, and decision processes. It does not promise API stability, compatibility with this repository, maintenance speed, or a particular licence. The Agentic AI Foundation, a Linux Foundation home for open agentic-AI projects, hosts agentgateway — whose role here spans MCP, A2A, model, API, policy, and observability traffic. That membership is a fact about governance and changes nothing about whether a given release works, which is why the repository pins one exact gateway release and validates its concrete routes.

Stewardship is therefore the wrong place to look when something breaks. Look at the pin:

```bash
rg -N 'a2a-go/v2|modelcontextprotocol/go-sdk|openai-go/v3|opentelemetry.io/otel v' agents/go/go.mod | awk '{print $1, $2}'
```

```text
github.com/a2aproject/a2a-go/v2 v2.4.0
github.com/modelcontextprotocol/go-sdk v1.7.0
github.com/openai/openai-go/v3 v3.49.0
go.opentelemetry.io/otel v1.44.0
```

Four contracts, four upstream modules, four exact versions — printed as module and version only, with each line's trailing compatibility comment cut by the `awk`. That is the tuple an upstream maintainer needs from you, and none of it is derivable from knowing which foundation hosts what.

**You can now open a report that names the exact module and version that failed — the line a maintainer would otherwise have to ask you for before anything else can start.**

| Home                       | Course components or contracts                                  |
| -------------------------- | --------------------------------------------------------------- |
| Agentic AI Foundation / LF | agentgateway                                                    |
| Linux Foundation           | A2A and MCP protocol projects                                   |
| CNCF                       | Kubernetes, Prometheus, OpenTelemetry, and Sandbox-stage kagent |
| Google                     | ADK Go and the optional Gemini/Vertex integration               |
| Grafana Labs               | Grafana, Tempo, and Loki                                        |
| project/vendor communities | Ollama runtime and Qwen open weights                            |

Treat those rows as a starting point and the current project pages as the authority, because stewardship and maturity both move. Governance answers _who changes a project_. A lock and a compatibility test answer _whether this repository supports the change_.

Provider portability follows the same split. The Go model adapter keeps the transport-specific client behind it, so moving from direct Ollama to the gateway changes `OPENAI_BASE_URL` while `AGENT_MODEL_PROVIDER` and typed model construction keep the application seam explicit, and native Gemini stays a separate optional path. Standardized calls are not standardized behavior, though: a new provider and model pair is only supported once the black-box evalset, its required cases, cost bounds, and any applicable judge calibration have passed for a recorded source revision and model identity.

## Route the failure to the narrowest owner

Reduce the problem to one contract before you write a word. Reproduce it against the repository pin and, when practical, against the version upstream currently supports. Strip credentials, personal data, prompts, responses, runtime databases, and private infrastructure. Supply the smallest protocol payload or configuration that still fails, follow the upstream security policy for anything exploitable, and link a temporary workaround only when it helps someone else reproduce the gap. Sending the whole course checkout when one wire request and a version tuple would do is how a good report becomes an ignored one.

| Failure surface                          | Owning project to inspect first             |
| ---------------------------------------- | ------------------------------------------- |
| listener, route, policy, gateway metrics | agentgateway                                |
| MCP message or Go SDK behavior           | MCP specification or MCP Go SDK             |
| A2A message, task, stream, cancellation  | A2A specification or A2A Go SDK             |
| ADK runner, callbacks, launcher, model   | Google ADK Go                               |
| kagent CRD or controller                 | kagent                                      |
| Kubernetes API or NetworkPolicy          | Kubernetes                                  |
| OTLP SDK, Collector, exporter            | OpenTelemetry project owning that component |
| Tempo, Loki, or Grafana query/UI         | the corresponding Grafana Labs project      |

Two worked examples, neither requiring a code change. If `kubectl apply` rejects a `v1alpha2` field in a kagent resource, the narrow owner is kagent, the pinned version lives in the chart in the helmfile, and the sanitized reproduction is the smallest rejected manifest with your identifiers removed — with the overlay you control as the only place to work around it.

If the Go OTLP exporter reports a protocol error before a span reaches the collector, the narrow owner is whichever OpenTelemetry component failed, and the error message usually says which. The pinned version is the module line you printed above, and the reproduction is one span with a minimal collector configuration.

The repository's own tracker owns integration mistakes and course claims. An upstream tracker owns a minimal bug in its own contract. Getting that split right is most of what makes a report land.

## AGENTS.md is a repository convention, not a runtime protocol

`AGENTS.md` is a vendor-neutral instruction convention for coding agents editing this repository. The deployed AgentOps Agent never reads it, no network service speaks it, and it replaces neither MCP nor A2A. The repository dogfoods the convention by keeping operational rules, owners, and limits in that one root file — which makes it easy to mistake for part of the runtime, and it is not.

## What you can do now

- You can tell foundation stewardship, software licence, project maturity, and repository compatibility apart.
- You printed the exact upstream module and version behind each of the four open contracts.
- You can route an MCP, A2A, gateway, kagent, ADK, or telemetry failure to its narrow owner with a sanitized reproduction.
- You can say why a provider swap needs a recorded evaluation run rather than a successful HTTP response.

"Something in the stack is broken" is answerable: name the project that owns the failing contract, print the version it failed at, and hand both to the person who can fix it.
