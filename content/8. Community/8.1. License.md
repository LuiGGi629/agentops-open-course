## A public repository is not a reusable one

You copy `infra/` into your company's platform repo because the manifests are exactly what you need. Eighteen months later, someone in legal asks under whose terms that code is running in production. If the permission notice did not travel with those files, the honest answer is "we do not know" — and in copyright law, not knowing defaults to _no_. Visibility is not permission. Copyright reserves copying, modification, and redistribution to the author until an explicit grant says otherwise, so a repository can be perfectly public and still be unusable by anyone else.

This repository makes three separate grants, because software and teaching material are reused by different people for different reasons:

| Material                       | License                                                   |
| ------------------------------ | --------------------------------------------------------- |
| software, manifests, skills    | [MIT](https://opensource.org/license/mit)                 |
| course prose and diagrams      | [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) |
| bundled Inter and Outfit fonts | [SIL Open Font License 1.1](https://openfontlicense.org/) |

The root `LICENSE` carries the MIT software grant, `static/LICENSE.txt` carries the course-content grant, and `static/assets/fmind/OFL-1.1.txt` carries the font notices. MIT is a short permissive software licence whose one real obligation is keeping its copyright and permission notice with substantial copies.

CC BY 4.0 is built for creative work instead. It allows reuse and adaptation, including commercially, as long as attribution, a licence link, and an indication of what you changed travel with the material, and as long as you add no restriction that stops the next person doing the same. Using one licence for both audiences would force each of them to interpret terms written for the other.

These summaries are an engineering guide, not legal advice. Read the licence text before you redistribute a derivative.

## The notice travels with the directory, not with the repository

Someone who copies `agents/` receives a directory, not a repository — so the grant has to be inside it. Four distributable subtrees therefore carry their own copy, and the copies are not allowed to diverge:

```bash
sha256sum LICENSE agents/LICENSE clients/LICENSE infra/LICENSE load/LICENSE
```

```text
b20626e1f04ad0cfd44fced6cccbebaca919619a2336d7a6d785f0293f2de8d0  LICENSE
b20626e1f04ad0cfd44fced6cccbebaca919619a2336d7a6d785f0293f2de8d0  agents/LICENSE
b20626e1f04ad0cfd44fced6cccbebaca919619a2336d7a6d785f0293f2de8d0  clients/LICENSE
b20626e1f04ad0cfd44fced6cccbebaca919619a2336d7a6d785f0293f2de8d0  infra/LICENSE
b20626e1f04ad0cfd44fced6cccbebaca919619a2336d7a6d785f0293f2de8d0  load/LICENSE
```

One digest, five files. `scripts/check-licenses.sh` runs `cmp` over exactly that set, so an edit to one copy fails instead of silently creating two different MIT grants in one project. Exactly that set is also the limit of what the comparison covers: lift a folder out of `skills/`, which ships no copy of its own, and nothing comes with it unless you bring the notice yourself.

The same logic decides which licence covers a quoted excerpt. When a page pulls in a Go function through a named include, the surrounding explanation is CC BY 4.0 course content and the extracted function stays MIT-licensed software. Because the include names the repository path and region, that provenance is visible rather than inferred — [8.0. Repository]({{< relref "/8. Community/8.0. Repository.md" >}}) shows how to find the source it points at.

For a derivative, that means two habits. Keep the MIT notice beside copied software. For adapted prose, write a visible attribution that names the course and author, links the source, links CC BY 4.0, and says what you changed — and do not imply the original author endorses your version.

## One command, and it looks past the agent

Licence drift is boring to check by hand and cheap to check by machine:

```bash
mise run check:licenses
```

```text
[check:licenses] $ ./scripts/check-licenses.sh full
repository licenses: MIT software + CC BY 4.0 course content + OFL 1.1 fonts

Report Summary

┌──────────────────┬───────┬──────────┐
│      Target      │ Type  │ Licenses │
├──────────────────┼───────┼──────────┤
│ agents/go/go.mod │ gomod │    -     │
├──────────────────┼───────┼──────────┤
│ evals/go.mod     │ gomod │    -     │
├──────────────────┼───────┼──────────┤
│ go.mod           │ gomod │    -     │
├──────────────────┼───────┼──────────┤
│ tools/go.mod     │ gomod │    -     │
├──────────────────┼───────┼──────────┤
│ agents/go/go.mod │   -   │    0     │
├──────────────────┼───────┼──────────┤
│ evals/go.mod     │   -   │    0     │
├──────────────────┼───────┼──────────┤
│ tools/go.mod     │   -   │    0     │
└──────────────────┴───────┴──────────┘
```

Three timestamped `INFO` lines and the closing legend are cut; the rest is verbatim, separators included. In that legend, `0` means clean and `-` means not scanned for that class. The first line is the repository's own notice check; everything below it is `trivy-repository.sh licenses` walking the whole checkout at UNKNOWN, HIGH, and CRITICAL severity.

Because it walks the tree rather than a configured list, it finds every `go.mod` present: the root Hugo module plus the three Go modules that ship code — `agents/go/go.mod`, `evals/go.mod`, and `tools/go.mod`. That breadth is the point. A dependency review that inspects only the production module, and skips the evaluation harness and the repository tooling, has reviewed a fraction of what you would be shipping.

`mise run check:licenses:core` currently calls the same policy. Keeping the learner and maintainer vocabulary pointing at one implementation is cheaper than maintaining a weaker duplicate that quietly disagrees.

**One command just confirmed that the four distributable subtrees still carry byte-identical copies of the root MIT grant, and that no dependency arrived with a licence nobody reviewed.**

A scanner reads declared metadata, which can be missing, malformed, or overbroad, so read that green as an observation about declared licences rather than as a legal opinion — [0.2. Evidence]({{< relref "/0. Overview/0.2. Evidence.md" >}}) draws that line for the whole course.

Image scans come at the same question from the other side. The repository scan sees locks, manifests, and vendored assets before any image exists; the image scan sees the packages actually present in the built artifact, using the same `trivy.yaml` policy against the exact candidate.

## Your turn: let one subtree copy drift and see which one is named

Predict before you touch anything: if a well-meaning contributor updates the copyright year in `agents/LICENSE` and nowhere else, does the repository end up with two MIT grants, one warning, or a red run?

- **Mode**: `temporary experiment`.
- **Goal**: watch the notice check identify the specific copy that drifted, rather than reporting that "licences" are wrong.
- **Files to touch**: only `agents/LICENSE`, restored at the end. The root `LICENSE` is never edited.
- **Preflight**: `git diff --quiet -- agents/LICENSE` must exit 0, and `mise run check:licenses` must currently pass.
- **Steps**: change one character in `agents/LICENSE` — a year, a name, a line break — then run `mise run check:licenses` and read the first line it prints on stderr.
- **Gate that proves completion**: the task exits non-zero with `agents/LICENSE: software license differs from the root MIT license`, and you can say why the check compares bytes instead of parsing the text.
- **Final state**: run `git restore -- agents/LICENSE`, then confirm `mise run check:licenses` is green again and `git status --short` shows no leftover change.

Byte comparison rather than parsing is the whole trick. Two MIT grants that differ by a rewrapped line are still two documents a lawyer has to read separately, and a checker clever enough to call them equivalent is a checker that will one day call two genuinely different grants equivalent too.

## Picking a licence for what you build next

Choose from your project's ownership and distribution intent, never from its language or framework. For an open-source derivative, preserve the notices attached to any MIT software you copied and pick a compatible licence for your original code. For private or employer-owned work, follow the rights holder's policy. Never paste this course's licence header into a project whose owner chose different terms: a wrong grant is worse than a missing one, because a missing one prompts the question and a wrong one looks settled.

Citation is a separate obligation from either grant. `CITATION.cff` is this repository's structured citation authority, which GitHub and reference managers render into common formats. It complements the CC BY 4.0 attribution requirement and the MIT notice requirement; it does not discharge either.
