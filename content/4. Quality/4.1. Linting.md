## How do you format and check the agent?

Run the module vocabulary from its directory:

```bash
cd agents/go
mise run format
mise run check
git diff --check
```

Review formatter changes before keeping them. The check must finish without warnings; a warning is a failed correctness gate, not optional polish.

## Which tools own Go source?

`goimports` groups imports and applies base formatting. `gofumpt` adds a stricter, deterministic style. `golangci-lint` v2 checks the same formatter policy without writing and runs the configured analyzers.

The v2 configuration is explicit:

- `version: "2"` selects the current schema.
- `formatters` enables `goimports` and `gofumpt` with the repository prefix and extra rules.
- `linters` adds security, errors, SQL resource handling, structured logging, spelling, performance, and unused-code checks.
- `govet.enable-all: true` turns on every applicable `go vet` analyzer through the aggregate.

Run raw `go vet ./...` while diagnosing an analyzer, but keep `mise run check` as the canonical gate.

Known-vulnerability analysis is a separate networked boundary. `mise run check:vuln` runs `govulncheck` across the `agents/go`, `evals`, and `tools` modules; the offline commit gate does not pretend a stale or unavailable vulnerability database is current evidence.

## Which checker owns the other files?

| Surface                       | Primary checker                            |
| ----------------------------- | ------------------------------------------ |
| Go source and imports         | `gofumpt`, `goimports`, `golangci-lint` v2 |
| Markdown, JSON, TOML, YAML    | dprint                                     |
| Course structure and includes | Repository convention checker              |
| Shell                         | ShellCheck plus repository contract checks |
| Workflows                     | actionlint, offline Zizmor, pinned actions |
| Kubernetes and OpenTofu       | Renderers plus configuration scanners      |

All are reached through mise tasks so local hooks and hosted CI use the same commands.

## Why combine analyzers?

The compiler answers whether code can build. Static analyzers answer different questions: is an error ignored, a response body leaked, an SQL handle left open, a structured log malformed, or a copy made accidentally?

An aggregate is useful only when findings remain actionable. Each enabled analyzer has a concrete failure class represented in the codebase.

## What does a legitimate exception look like?

Prefer changing the code. When an analyzer is wrong for one exact site, scope the exception to one rule and place a short reason beside it.

Test code has a narrow `gosec` exception because fixtures intentionally construct inputs that production code must reject. That does not disable security analysis over production packages.

Never blanket-exclude a directory, hide an entire analyzer, or add a suppression merely to force green.

## How do local hooks and CI stay aligned?

Git hooks delegate to mise instead of copying command flags. Hosted CI invokes the same repository tasks on a clean runner.

The main CI workflow first uses `install:validation`, then runs the base doctor, checks, and tests. The documentation workflow installs only its pinned documentation and browser toolchains before rendering and browser checks. Neither workflow starts a model or platform service or installs cloud or release-only tools.

This alignment proves command equivalence, not exact-head CI success. A local green run remains local evidence until the candidate commit passes the hosted workflow.

## Why do documentation checks belong here?

Course pages are executable interface documentation. The structural gate checks front matter, question headings, navigation, source includes, link labels, diagrams, and closing proof contracts.

Hugo then renders with warnings treated as errors. A missing source region or bad internal reference fails before the site can ship misleading code.

## What proves this page worked?

Run the focused and repository documentation checks:

```bash
cd agents/go
mise run check
cd ../..
mise run check:docs
git diff --check
```

**You are done when:**

- `golangci-lint` v2 reports no formatter or analyzer finding.
- Re-running the formatter makes no further change.
- The documentation convention gate exits successfully.
- `git diff --check` reports no whitespace error.
- You can name which tool owns a `.go`, `.md`, `.sh`, and workflow file.
- Every remaining suppression is narrow and has a source-local reason.
