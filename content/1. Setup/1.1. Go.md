{{% admonition abstract "In one glance" %}}

- **You will:** Install the Go toolchain, inspect the agent module, and run its offline checks and tests.
- **You need:** `mise run install` finished and `mise run doctor` passing from [1.0. System]({{< relref "/1. Setup/1.0. System.md" >}}).
- **Time:** about 18 minutes, hands-on. {{% /admonition %}}

## How do you prepare the Go module?

The agent is a standalone Go module under `agents/go`; the repository root owns the pinned tool versions.

```bash
cd agents/go
mise run install
mise run check
mise run test
```

These commands download module dependencies, check formatting and static analysis, then run the offline suite with the race detector. They do not start a model, container, cluster, or cloud resource.

## Why does the course use one Go toolchain?

One compiled language keeps the learner path, runtime, evaluation harness, and repository tools on the same dependency model. The compiler rejects many invalid states before a model can exercise them.

`mise.toml` pins the toolchain used across the repository. The `go` directive in `agents/go/go.mod` must match that pin, while `go.sum` records exact module checksums.

```bash
mise current go
sed -n '1,8p' agents/go/go.mod
```

Treat those files as authority. A version copied into prose is only an explanation and can drift.

## What does the module declare?

The first `require` block lists direct runtime dependencies: ADK, A2A, the model clients, OpenTelemetry, MCP, configuration, and pure-Go SQLite.

{{< include path="agents/go/go.mod" region="runtime-dependencies" lang="go" >}}

The second block contains transitive requirements selected by the module solver. Do not hand-edit it to remove unfamiliar entries; change direct requirements with `go get` or `go mod tidy`, then review the resulting diff.

## What does the `tool` directive solve?

The module also records development executables with Go's `tool` directive. That makes their source versions part of the module graph without importing them into the agent binary.

```bash
cd agents/go
go tool goimports -h >/dev/null
go tool gofumpt -h >/dev/null
go tool govulncheck -version
```

The repository still pins command-line launchers such as `golangci-lint` and `gotestsum` in root `mise.toml`. Modules own libraries and Go tools; mise owns the cross-repository executable vocabulary.

## Which commands should you remember?

Run the short task names instead of reconstructing raw flags:

| Intent                          | Command             | Boundary                       |
| ------------------------------- | ------------------- | ------------------------------ |
| Synchronize the module          | `mise run install`  | May download dependencies      |
| Rewrite Go formatting           | `mise run format`   | Writes source files            |
| Check format and lint           | `mise run check`    | Offline after install          |
| Run tests and the race detector | `mise run test`     | Offline, writes `coverage.out` |
| Inspect measured coverage       | `mise run coverage` | Evidence only                  |
| Build the production binary     | `mise run build`    | Offline after install          |

There is deliberately no enforced Go coverage percentage. The owner has not selected one, so the repository reports measured coverage as evidence and never presents it as policy.

## Why does the offline gate avoid model configuration?

Deterministic checks should fail only because source or fixtures are wrong. A shell credential, an unavailable endpoint, or a stochastic answer would make a poor commit gate.

Model-backed commands such as `mise run run` load the repository configuration explicitly. `mise run check` and `mise run test` do not, which lets them run on a clean checkout without a model or account.

## How do you inspect the dependency graph safely?

Use module-aware commands from the module directory:

```bash
cd agents/go
go list -m all
go mod verify
go list -deps ./... >/dev/null
```

`go mod verify` checks downloaded content against `go.sum`. It does not replace vulnerability, licence, or provenance review; those belong to the repository security gates.

## What proves this page worked?

Run the model-free checkpoint once more:

```bash
cd agents/go
mise run check
mise run test
mise run coverage
```

**You are done when:**

- `mise run check` exits without formatting or lint findings.
- `mise run test` reports no failures and the race detector reports no race.
- `mise run coverage` prints the measured package and total coverage without claiming a required percentage.
- You can explain why `go.mod`, `go.sum`, the `tool` directive, and root `mise.toml` have different jobs.
- All three commands finish without a model server, container engine, cluster, cloud resource, or credential.
