## How is the MCP route secured?

Security is layered at server, gateway, and client boundaries.

- The Go server registers only six reads and applies Host/Origin allowlists.
- agentgateway applies its configured target and policy allowlist, rate limit, authentication profile, and failure mode.
- The ADK Go MCP toolset filters again with `compose.MCPReadToolNames()` and applies an HTTP deadline.
- Guarded writes remain in-process and never cross this route.

No single configuration file is trusted to preserve the full boundary by itself.

## How do you list tools through the gateway?

Use the executable Go smoke client rather than hand-maintaining a JSON-RPC transcript.

```bash
mise run smoke:host
```

The smoke starts isolated raw MCP, A2A, fake model, and gateway processes on allocated ports. Its Go MCP client connects through the gateway, performs the negotiated handshake, lists tools, and compares sorted names with `compose.MCPReadToolNames()`.

The task tears down the processes it owns. It makes no live model or paid provider call.

## What does a denied tool call look like?

A name outside the gateway or client allowlist never becomes an invocable ADK tool.

The focused tests register a valid-looking write and an extra tool with injected description text. Discovery through the client returns only the six approved reads. Directly calling a denied gateway target returns protocol failure without reaching the backend implementation.

```bash
cd agents/go
go test ./compose ./mcpserver -run 'MCP|Allow|Filter|Denied'
```

## What does failClosed actually decide?

`failClosed` decides whether a request is denied when an external policy or target check cannot produce a trustworthy answer.

It does not make the backend correct or available. A closed policy may trade availability for confidentiality or authorization. The course uses that trade for security-critical remote checks and tests the unavailable-policy path explicitly.

## Why re-list tools the MCP server already restricts?

The gateway and client may be connected to a different, upgraded, or compromised server.

Tool names, descriptions, and schemas reach the model as instruction-like input. A closed list at every trust boundary prevents an upstream change from silently widening capability or injecting new tool prose.

The infrastructure conventions gate asserts that the configured gateway list and executable Go list agree.

## Why are write tools absent?

Remote writes would move confirmation, identity, transaction, and audit authority across a broader network surface.

`restart_service` and `resolve_incident` stay inside the Go application, where the handler can validate ADK confirmation and verified identity and commit state plus audit in one transaction.

## Which address does the container really dial?

The canonical host config names loopback upstreams, and the hardened wrapper renders the container-reachable addresses at runtime.

On Docker Desktop, `host.docker.internal` reaches the host. On native Linux, the native Go loopback relay binds only the wrapper-owned bridge address and forwards to the loopback MCP, A2A, and model services. Those services remain unexposed on the host network.

Kubernetes uses service DNS such as `agentops-mcp.agentops.svc.cluster.local:8000/mcp` instead of the host bridge.

## How does the deployed agent select this path?

The conversational entrypoint reads `AGENT_MCP_URL` and constructs the filtered HTTP toolset.

An optional `AGENT_MCP_TOKEN` becomes a bearer credential through ADK's credential provider. The HTTP client uses `AGENT_TOOL_TIMEOUT_S`. Workflow and coordinator specialists ignore the remote switch and retain their local restricted tool sets.

The exact constructor is `agents/go/compose/mcp.go`; its tests prove extra tools never join the request.

## What does the rate limit guarantee?

The local token bucket bounds requests per gateway instance over its configured refill interval.

It is not a user quota, distributed limit, concurrency bound, or cost budget. Restarting or scaling an instance changes available tokens. Per-session token budgets and model-call caps are separate application controls.

## Your turn: how do you take one tool off the allowlist?

Change the executable client list and every policy owner together, then prove the absence from both raw composition and governed discovery.

- **Mode**: temporary policy experiment.
- **Goal**: prove one removed read disappears from client construction and governed discovery.
- **Files to touch**: `agents/go/compose/mcp.go` and the matching agentgateway profiles and tests.
- **Preflight**: require those paths to have no existing diff and record the current six-name list.
- **Gate that proves completion**: focused Go tests, `mise run check:infra`, and `mise run smoke:host` all observe the reduced list.
- **Final state**: restore the experiment paths and rerun the same gates to return to the documented six-read contract.

1. Remove one read name from the intended public contract.
1. Update `compose.MCPReadToolNames()` and the matching gateway policy.
1. Keep the server's local implementation only if another entrypoint still needs it.
1. Run focused Go tests, infrastructure conventions, and host smoke.

A gateway-only edit is incomplete because the application could still accept the tool on a direct or differently routed server.
