{{% admonition abstract "In one glance" %}}

- **You will:** Run one grounded agent turn, inspect the composed Go agent, and verify it without a model.
- **You need:** The base and model doctor profiles passing with `qwen3:4b-instruct` available in Ollama.
- **Time:** about 30 minutes, hands-on. {{% /admonition %}}

## What are you about to run?

You will run the same Go binary used by the console, web UI, A2A server, MCP server, workflow, and coordinator tasks.

The conversational entrypoint can inspect a fictional incident dataset through typed tools. It may recommend an action, but a state-changing tool still requires explicit confirmation and attributable identity.

## How do you prove the live model boundary?

Run the model doctor before starting the inspectable web surface.

```bash
mise run doctor:model
cd agents/go
mise run web
```

The first command verifies the configured live model. The second starts ADK's developer UI and REST API on `http://localhost:8002`; it blocks until you stop it with `Ctrl-C`.

{{% admonition warning "A model turn is not an offline gate" %}}

This surface calls the configured model and may take tens of seconds on CPU. The focused Go tests later on this page make no model call. {{% /admonition %}}

## How do you inspect a grounded turn?

Open the ADK web UI, select the `agent` application, and ask:

```text
List the three open incidents.
```

Open that turn's Events view and find this evidence in order:

1. A function call to `list_incidents` with `status` set to `open`.
1. Its function result containing seed rows for `INC-002`, `INC-005`, and `INC-010`.
1. The final model response naming only identifiers present in that result.

Compare the final identifiers with the observed result. Every identifier in the answer must be a subset of those returned rows; wording and order may vary.

## Why is a correct-looking answer not enough?

Matching the seed identifiers proves nothing about how the model obtained them.

Without the observed function call and result, the answer might come from prompt leakage, memorized context, or a lucky guess. Grounding evidence binds the final claims to evidence captured in the same turn.

## When is the console preview useful?

The console is a fast live preview when you only need to see the final answer.

```bash
cd agents/go
mise run run
```

Ask the same question, but label the output correctly: the console does not expose enough event evidence to prove the tool trajectory or grounding.

## What is in the dataset the agent reads?

`agents/data/` is immutable seed input.

- `incidents.db` contains fictional incidents and an append-only audit schema.
- `logs/` contains service logs used by search tools.
- `runbooks/` contains reviewed operational guidance.
- `skills/` contains runtime Agent Skills loaded under explicit allowlists.

The writable runtime copy lives under `agents/go/.state`. Reads never mutate the seed. Only A2A startup and direct write boundaries may prepare or migrate runtime state.

## How is the root agent defined?

Composition is explicit Go code, not discovery by import convention.

{{< include path="agents/go/compose/composition.go" region="root-agent" lang="go" >}}

The constructor receives its model, tools, policy, and services as typed dependencies. Tests can replace each boundary with a fake without changing process-wide state.

## Which module owns each tool and policy hook?

| Responsibility                                         | Package                                |
| ------------------------------------------------------ | -------------------------------------- |
| Incident and log reads                                 | `agents/go/tools`                      |
| Runbooks and retrieval                                 | `agents/go/memory`                     |
| Runtime SQLite state                                   | `agents/go/data` and `agents/go/state` |
| Tool timeouts and circuit breaking                     | `agents/go/resilience`                 |
| Budget, compaction, redaction, and injection hardening | `agents/go/policy`                     |
| Telemetry setup and sanitized export                   | `agents/go/telemetry`                  |

The app-wide plugin is attached once. Adding a sub-agent or workflow node therefore does not silently lose policy.

## When does the agent use MCP instead of local tools?

Only the conversational entrypoint switches its six read/runbook capabilities to remote MCP when `AGENT_MCP_URL` is set.

Workflow and coordinator specialists keep local tools. Guarded writes always remain in-process. The remote toolset applies an explicit read-name filter so a server cannot widen authority by advertising extra tools.

## How does the agent fail fast on bad configuration?

`config.Load()` parses the environment into `config.Config`, validates cross-field invariants, and returns all discovered problems before a runtime is built.

```bash
cd agents/go
mise run config:check
```

The command prints effective non-secret settings, masks credentials, and exits non-zero on invalid provider, endpoint, timeout, identity, state, or policy combinations.

## Why must importing the agent package stay side-effect-free?

Go package initialization should not open databases, start exporters, load environment files, or dial services.

The command layer owns those effects and threads constructed values downward. This makes package tests deterministic, prevents a helper import from starting a runtime, and keeps resource cleanup explicit.

Environment loading is task-scoped. Deterministic `go test`, formatting, linting, and evaluation-asset validation do not load the repository `.env`.

## Can you verify the agent without a model?

Yes. Fakes exercise composition, tool contracts, policy, and command dispatch without a network call.

```bash
cd agents/go
go test ./compose ./tools ./policy ./cmd/agent
```

The suite also runs under the race detector through `mise run test`. It reports measured coverage, but no percentage threshold is enforced.

## What proves this page worked?

Capture both boundaries separately:

```bash
cd agents/go
go test ./compose ./tools ./policy ./cmd/agent
mise run config:check
```

Then, only with the local model already running, repeat the ADK web inspection above.

**You are done when:**

- The focused tests and configuration check pass without a model call.
- The web Events view shows `list_incidents(status="open")`, its returned rows, and the final response in one turn.
- Every final incident identifier is a subset of the identifiers in that observed tool result.
- You can explain why the console's same correct-looking identifiers are plausible output, not grounding proof.
- You can explain why remote MCP never carries guarded write authority.
- You know that measured Go coverage is evidence, not an enforced threshold.
