## What is a session?

An ADK session is the conversation state for one application, user, and session identifier.

```bash
cd agents/go
go test ./a2aserver
```

It contains events and application state used across turns. The Go reference uses ADK's database session service backed by SQLite so a server restart does not automatically erase a conversation.

## What is an A2A task, and how does it differ from a session?

An A2A task is protocol-visible work with its own id, context id, status, messages, artifacts, and cancellation lifecycle.

The context id maps to the logical ADK session. Several task operations can therefore belong to one conversation, while task state remains queryable through the network protocol. The server persists sessions and tasks in separate SQLite databases under the same state directory.

## How do you inspect the session server without calling a model?

Start the A2A surface in one terminal:

```bash
cd agents/go
mise run a2a
```

Then inspect its probes and card from another terminal:

```bash
xh GET http://127.0.0.1:8080/livez
xh GET http://127.0.0.1:8080/healthz
xh GET http://127.0.0.1:8080/.well-known/agent-card.json
```

These reads do not submit a model task. Liveness proves the process loop; readiness additionally checks runtime state and the session/task store schemas.

## Why does persistence matter?

Durable state lets a client recover task status after a process restart and keeps a multi-turn context coherent.

SQLite is appropriate for this single-replica course lab. The server uses a transaction mode and per-session invocation gate that serialize conflicting writes while allowing unrelated sessions to progress concurrently. Multiple replicas would require a shared database and an explicit migration, backup, and concurrency design.

## Who closes runtime resources?

The command layer owns every resource it opens and closes them during bounded shutdown.

{{< include path="agents/go/a2aserver/serve.go" region="a2a-lifespan" lang="go" >}}

Startup recovers an interrupted restore, publishes the writable dataset, prepares the session and task schemas, and only then becomes ready. Shutdown stops new work, drains in-flight turns up to the configured bound, and closes stores and servers.

## What changes when you deploy this server?

The listener and advertised address become separate contracts.

- The container listens on `0.0.0.0:8080` so the kubelet and gateway can reach it.
- The agent card advertises a callable host and port, never the wildcard listener address.
- `AGENT_DRAIN_TIMEOUT_S` bounds graceful shutdown and must remain below the Pod termination grace period.
- Readiness remains read-only after startup; probes never migrate or publish state.

Transactions and persisted tasks preserve correctness. The drain window only reduces avoidable interruption.

## How do you reset course state?

Stop every writer before resetting the disposable runtime copy.

```bash
cd agents/go
mise run data:reset
```

The state boundary serializes backup and restore with a process lock and three-phase journal. Never replace it with direct multi-file copies, and never delete unexplained `.restore-*` evidence.

## What proves this page worked?

Run the lifecycle and schema tests offline:

```bash
cd agents/go
go test ./a2aserver ./state ./cmd/agent
```

If you started the server, stop it with `Ctrl-C` and run `mise run data:reset` only after the process exits.
