## What do tokens, context, and parameters actually mean?

A language model predicts the next token from the context supplied for one request.

That makes generation **probabilistic**: the same request can produce different valid-looking outputs. It is also **stateless**: model weights do not remember the last turn. The Go session service rebuilds selected history and state into each request, while repeated evaluation reveals variance.

A **token** is a chunk of input or output text. The **context window** is the maximum token budget shared by instructions, history, tool schemas, tool results, and the generated answer. More context usually increases latency and, on priced providers, cost. The Go budget guard and compaction callback bound that envelope before a call is sent.

**Parameters** are the learned numbers in the model artifact, not current incident facts or durable memory. Tool reads and explicit stores provide current evidence. A model-generated tool call is therefore a proposal: typed argument validation, runtime policy, and human confirmation still decide whether an action may execute.

An **instruction-tuned** model is trained to follow conversational instructions and emit tool-call conventions. A base model only continues token sequences, so it is not this course's supported agent boundary without additional tuning and evidence.

**Open source** and **open weights** are different claims. Open weights make learned parameters available to run locally; they do not necessarily publish the training data and training code needed to reproduce them. The default Qwen weights are Apache-2.0 licensed and locally runnable, while the course reports that precise boundary instead of calling the whole model-development process open source.

## What contract does ADK require from a model?

ADK Go keeps the portability boundary deliberately small. A model implements two methods:

```go
// simplified: the installed ADK interface also carries package documentation.
type LLM interface {
	Name() string
	GenerateContent(context.Context, *LLMRequest, bool) iter.Seq2[*LLMResponse, error]
}
```

`Name` identifies the implementation. `GenerateContent` accepts the typed request and yields responses or errors, with the final response carrying usage metadata when the provider supplies it.

The agent composes against this interface, not a provider SDK. Tests replace only this boundary with a scripted model while leaving ADK, plugins, tools, sessions, and state real.

## What travels over the local wire?

The default adapter sends OpenAI Responses API requests to `/v1/responses`. The route is pinned by offline contract tests in `agents/go/model/openai_test.go`.

With Ollama already running, inspect the boundary directly:

```bash
curl --fail-with-body http://127.0.0.1:11434/v1/responses \
  -H 'Authorization: Bearer local-ollama' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "qwen3:4b-instruct",
    "input": "What is the status of checkout-api?",
    "tools": [{
      "type": "function",
      "name": "get_service_status",
      "description": "Return one service status",
      "parameters": {
        "type": "object",
        "properties": {"name": {"type": "string"}},
        "required": ["name"],
        "additionalProperties": false
      }
    }]
  }'
```

This is a live, stochastic model call. It is an observation, not an offline gate, and the exact wording may differ between runs.

## How does a model call become a tool call?

ADK serializes each tool declaration into the request. A capable instruction-tuned model can answer with a function-call item containing a name and arguments.

Those arguments remain untrusted. ADK decodes the shape, then the agent normalizes identifiers and validates domain rules before any read or write executes.

The model proposes; typed boundaries decide what is expressible; policy and human approval decide what is allowed.

## Which settings select the provider?

Configuration parses provider names and cross-field requirements once at startup:

{{< include path="agents/go/config/config.go" region="settings-provider-fields" lang="go" >}}

The stable selection surface is:

| Setting                | Default role                                               |
| ---------------------- | ---------------------------------------------------------- |
| `AGENT_MODEL_PROVIDER` | Chooses the ADK adapter family                             |
| `AGENT_MODEL`          | Chooses the model artifact                                 |
| `OPENAI_BASE_URL`      | Chooses direct Ollama or agentgateway                      |
| `OPENAI_API_KEY`       | Supplies the adapter credential or local non-secret marker |

Move from direct Ollama to the host gateway by changing only `OPENAI_BASE_URL` from `http://127.0.0.1:11434/v1` to `http://127.0.0.1:4000/v1`. The agent composition and tools stay unchanged.

## How does the factory preserve portability?

The factory constructs a concrete `model.LLM` and hands it to the agent:

{{< include path="agents/go/model/model.go" region="build-model" lang="go" >}}

This explicit construction matters because ADK does not resolve an arbitrary model name into a client. Endpoint, credential, timeout, and sampling settings are passed from validated configuration rather than inherited accidentally from process state.

An optional fallback model uses the same provider, endpoint, deadline, and connection pool. It is continuity within one trust boundary, not multi-provider failover.

## Which provider paths are supported?

The account-free path is OpenAI-compatible ADK through local Ollama. Chapter 5 inserts agentgateway on the same adapter contract.

Native Gemini is optional. API-key mode uses AI Studio; enterprise mode uses Application Default Credentials with an explicit project and location. These proprietary paths need an account and may incur cost, so they are comparisons rather than prerequisites.

The GKE overlay holds a compatibility-pinned model. Do not update it from prose alone; the gateway/model pair must pass the synthetic tool-result and stable-seed A2A smoke contracts first.

## How should you compare models?

Hold the code, dataset, prompt, decoding settings, transport, and state generation fixed. Run the same development evalset more than once and report pass rate, variance, tokens, model calls, latency, and failures.

Reset disposable state between candidates:

```bash
cd agents/go
mise run data:reset
AGENT_MODEL_TEMPERATURE=0 mise run run
```

Temperature zero reduces one source of variance; it does not make a model deterministic.
