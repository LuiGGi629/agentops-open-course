## Two kinds of green

A course about operating agents has a problem that a course about, say, compilers does not: some of what you build is deterministic, and some of it is a model that will answer differently on Tuesday. Both produce green checkmarks. They do not mean the same thing, and almost every bad decision in agent operations comes from treating the second as if it were the first.

So this course keeps two words apart, everywhere, on purpose.

A **gate** is deterministic. Same input, same verdict, every time, on your machine and in CI. `mise run check` is a gate. A schema validator is a gate. The audit-transaction test that proves a mutation and its audit row commit together is a gate. When a gate is green, the thing it checks is true — not likely, not usually. True.

An **observation** is a measurement of something that varies. An evaluation pass rate is an observation. A judge's agreement number is an observation. A latency figure is an observation. When an observation is good, you have learned something real about one run, on one machine, against one model, at one moment.

The distinction is not academic, and here is the shape of the mistake it prevents: an evaluation scored 14 of 15 last night, so the agent "passes evaluations", so the release is safe. Every step of that sentence is a small stretch, and the accumulated stretch is how a team ends up surprised by their own system at 02:00.

## The four places it bites

**Temperature zero is not determinism.** Setting temperature to `0` narrows a model's output distribution; it does not make a run reproducible. The same prompt against the same model can still take a different path, and it certainly will after a model update, a context change, or a different machine's floating-point behavior. This is why `mise run eval` samples every case three times rather than once, and why a single green run is not evidence that a case is stable. Repeats do not remove variance either — they let you see it.

**Coverage measures reach, not correctness.** This repository enforces 80% line coverage per package, and clearing that floor proves exactly one thing: the tests execute that much of the code. It says nothing about whether the assertions are worth anything. A test that calls a function and checks it did not panic raises coverage and proves nothing. Read the coverage number as "how much of this code is even looked at", never as "how correct this code is".

**A simulation is not production.** The local stack, the k3d cluster, and the seeded incident database are all real software doing real work, and none of them is your production environment. Load tests here run against a fixed dataset with no noisy neighbours. Kubernetes manifests render and apply, but a rendered manifest is not a cluster under contention. What the local path proves is that the mechanism is correct; what it cannot prove is how it behaves at your scale, with your data, under your failure modes.

**Absence of evidence is the most common false claim.** A green offline suite says nothing about whether the agent answered well, because it never called a model. A passing conventions check says nothing about whether the prose teaches anything. When this course tells you something is proved, it names the command that proved it, and when something is not proved, it says so rather than staying quiet and letting the green tick imply it.

## How to read the rest of the course

Every later page states its point plainly and, where a caveat matters, links back here rather than restating it. That is a deliberate trade: repeating a warning on forty pages trains you to skip it, and a warning you skip is worse than no warning, because it lets everyone believe the risk was communicated.

So when a page says a gate passed, take it literally. When it reports an observation, notice what varied and what did not. And when a page makes a claim with no command behind it, treat that as the page's opinion — including this one.

- You can say what a gate proves and what an observation suggests, and why the difference decides whether a release is safe.
- You can name the four distinctions this course refuses to blur: variance, coverage, simulation, and silence.
- You know that a later page's one-line caveat links here rather than repeating itself, and why that is deliberate.
