## The model had never heard of INC-002

It could not have. The incident lives in a SQLite file in this repository, and the model finished training long before that file existed. So when the agent is asked to list the three open incidents, its first move is not an answer. It is a request — the event ADK recorded, read back out of the session database:

```json
{ "functionCall": { "id": "nYN89WctgaMWcSCnlPw7LG5CxZRRfnTL", "args": { "status": "open" }, "name": "list_incidents" } }
```

Given a question it could not answer and a tool that could, the model asked. Rows come back from disk, and only then does it write prose. That chain — question, tool call, tool result, answer — separates a system you can operate from one that produces confident paragraphs, and it is why every chapter after this one exists: once an agent can touch real things, somebody has to decide what it may touch, prove it behaves, and watch it when it does not.

That turn ran on a laptop, against a model file on that laptop's disk. One command reports on the model side of it — and before you read its output, predict what a command named `doctor:model` does. Install Ollama? Start it? Something narrower?

```bash
mise run doctor:model
```

```text
[doctor:model] $ ./scripts/doctor.sh model
model      ready
env        optional .env is absent
ollama     0.32.6 with qwen3:4b-instruct ready on 127.0.0.1:11434
```

Something narrower: it probed and reported, installing nothing and starting nothing. Ollama and the multi-gigabyte Qwen3 download are prerequisites you put in place yourself in [1.4. Providers]({{< relref "/1. Setup/1.4. Providers.md" >}}), and this doctor's only job is to say in three lines whether they are where the agent expects them. Those three lines are also the entire model bill for the required path: a four-billion-parameter open-weight model answering from local disk, with no account, no API key, and no per-token fee.

## What you will have built

You start from a finished reference agent — an on-call assistant that reads incidents, logs, and runbooks for a fictional retailer and proposes remediation a human must approve — and take it through the operational lifecycle. First you give it capabilities: typed tools, Agent Skills, MCP, retrieval, workflows, and agent-to-agent calls. Then you make it accountable, with tests, behavioral evaluations, PII redaction, human approval, and an append-only audit trail. Then you put agentgateway in front of its traffic, ship it as one container image onto a local k3d cluster with kagent, and wire OpenTelemetry into self-hosted Tempo, Loki, Prometheus, and Grafana so you can watch a single turn end to end.

Every action and dataset stays local and fictional, which makes the boundaries real without making the consequences real. `main` is the finished reference; the capstone asks you to keep its platform contracts while replacing the example domain with your own. You need Git, a terminal, and basic Go.

## Pick a path, then stop deciding

| Path                  | Requires a model?    | Requires cloud? | What it gets you                                                                                       |
| --------------------- | -------------------- | --------------- | ------------------------------------------------------------------------------------------------------ |
| Offline engineering   | No                   | No              | Install, inspect the data, run the static checks and the deterministic test suite.                     |
| **Required OSS path** | Qwen3 through Ollama | No              | Every agent, gateway, platform, and observability outcome, account-free. **← take this one if unsure** |
| Optional provider     | Gemini               | Optional        | Compare ADK's native provider adapter after the local path works.                                      |
| Optional cloud lab    | Gemini on Vertex AI  | Yes             | Practise GKE, Workload Identity Federation, artifact storage, and immutable delivery.                  |

The required path costs no money and no signup; it spends your compute, storage, and electricity, and a slow CPU turn is the most common first-day friction. Gemini and Google Cloud usage can be billed, and [7.3. Costs]({{< relref "/7. Observability/7.3. Costs.md" >}}) owns the dated estimate you refresh before approving anything. Every required piece is open source, down to the Apache-2.0 Qwen3 weights and the Go evaluation harness; Gemini, Vertex AI, GKE, and GitHub hosting are proprietary services the course names as optional and never relabels.

## How to read the rest of it {#how-should-you-work-through-each-page}

Three conventions hold everywhere. Run commands from the repository root unless a block says otherwise. Every critical Go excerpt is included from source and re-checked when the site builds, so a page cannot drift from the code. ## What you can do now

- You can say what an agent does with a question it cannot answer, and why that move is the thing worth operating.
- You know which of the four paths you are taking, and that the default needs no account and no fee.
- You know what the required path spends instead: your own compute, and patience for a slow first turn.
- You know that [1.0. System]({{< relref "/1. Setup/1.0. System.md" >}}) begins the installation, and nothing before it needs anything installed.

Two decisions are now yours to defend out loud: whether an agent is worth operating at all, and which path through this one you are taking. Both answers are allowed to be "not this, not yet" — that is what makes them decisions rather than a syllabus.
